EntropyDice Documentation

EntropyDice is a REST API that generates cryptographically secure random numbers for role-playing game dice. It uses the kernel's CSPRNG (/dev/urandom) to provide true hardware entropy, ensuring fair and unbiased results.

Supports all standard RPG dice: D4, D6, D8, D10, D12, D20, D100 (percentile), as well as compound expressions like 4D6+D12 and modifiers like 2D8+1D20-4.

Quick Start

Install and run the server locally:

git clone <repo>
cd EntropyDice
npm install
npm start

Make your first roll:

curl "http://localhost:3000/roll?q=D20"
{"ok":true,"expression":"D20","groups":[{"dice":"D20","count":1,"rolls":[15],"subtotal":15}],"modifier":0,"detail":"[15]","total":15, ...}

API Endpoints

GET /

API information and health check. Returns version, available sources, and endpoint documentation.

GET /roll?q=<expression>&source=<source>&format=<format>

Roll dice. This is the main endpoint. All parameters except q are optional.

Dice Expressions

The q parameter accepts expressions following this grammar:

expr  → term (('+' | '-') term)*
term  → factor (('*' | '/') factor)*
factor → dice | number | '(' expr ')'
dice  → ('D' | 'd') number    (equivalent to 1Dn)
       | number ('D' | 'd') number
number → \d+

Operators follow standard mathematical precedence: * and / bind tighter than + and -. Parentheses can be used to override precedence.

Basic Examples

ExpressionMeaningExample Response (text)
D61 six-sided die[4] = 4
D201 twenty-sided die[17] = 17
D1001 percentile die[73] = 73
4D64 six-sided dice[4+2+6+1] = 13
3D83 eight-sided dice[5+3+7] = 15

Compound Expressions

ExpressionMeaningExample Response (text)
4D6+D124d6 + 1d12[4+2+6+1]+[9] = 22
2D8+1D202d8 + 1d20[5+3]+[17] = 25
D4+2D101d4 + 2d10[3]+[7+2] = 12

With Modifiers

ExpressionMeaningExample Response (text)
2D8+1D20-42d8 + 1d20 - 4[8+8]+[20]-4 = 32
D6+31d6 + 3[4]+3 = 7
3D6-23d6 - 2[4+2+6]-2 = 10
D6-D41d6 - 1d4[5]-[2] = 3

Complex Expressions

Multiplication (*), division (/), and parentheses are supported:

ExpressionMeaningExample Response (text)
D6*21d6 × 2[4]*2 = 8
D6*D41d6 × 1d4[5]*[3] = 15
D20/21d20 ÷ 2[17]/2 = 8.5
(2D6+3)*2(2d6 + 3) × 2([4+2]+3)*2 = 18
2*(D4+D6)2 × (1d4 + 1d6)2*([3]+[4]) = 14
(D10+3)/2(1d10 + 3) ÷ 2([7]+3)/2 = 5

Division returns floating-point results with up to 2 decimal places. Division by zero returns a 400 error.

URL encoding: Special characters must be URL-encoded in query parameters:
  • + → %2B
  • * → %2A
  • / → %2F
Example: 4D6%2BD12, %282D6%2B3%29*2

Response Formats

JSON (default)

Structured response with full roll details. Use for programmatic access.

GET /roll?q=2D8+1D20-4

{
  "ok": true,
  "expression": "2D8+1D20-4",
  "normalized": "2D8+1D20-4",
  "source": "crypto-pure",
  "groups": [
    { "dice": "D8", "count": 2, "rolls": [8, 8], "subtotal": 16 },
    { "dice": "D20", "count": 1, "rolls": [20], "subtotal": 20 }
  ],
  "modifier": -4,
  "detail": "[8+8]+[20]-4",
  "total": 32,
  "timestamp": "2026-07-04T12:00:00.000Z"
}

Text

Human-readable plain text. Use from terminal / curl.

GET /roll?q=2D8+1D20-4&format=text
[8+8]+[20]-4 = 32

HTML

Styled HTML page. Use in browser directly or embed in iframes.

GET /roll?q=2D8+1D20-4&format=html
<!-- Returns a full styled HTML page with dark theme -->

Opening the URL directly in a browser will show a nicely formatted result card with the expression, individual rolls, and total.

Raw

Just the number. Perfect for scripts that only need the result value.

GET /roll?q=2D8+1D20-4&format=raw
32

Randomness Sources

crypto-pure (default)

Uses crypto.randomInt() from Node.js, which calls the kernel's CSPRNG (getrandom() syscall → /dev/urandom). This provides true hardware entropy collected from:

  • CPU cycle jitter
  • Disk I/O timing variations
  • Network interrupt timing
  • Hardware random number generators (if available)

Each call is stateless and independent. No seed, no state, no sequence — every number is fresh entropy. Uses rejection sampling internally to eliminate modulo bias.

crypto-xoshiro-ng

Hybrid source that combines the speed of PRNG with the security of cryptographic entropy:

  1. Seed: 128 bits of true entropy via crypto.randomBytes(16)
  2. Generation: Xoshiro128++ algorithm (~200M numbers/sec)
  3. Noise injection: Each output is XOR'd with a microsecond-granularity timestamp
  4. Auto-reseed: New 128-bit seed every hour (configurable)

Ideal for high-throughput scenarios where you need both speed and non-deterministic behavior.

Use Cases

Being a standard REST API, EntropyDice can be called from any language or platform that supports HTTP requests. Below are common integration examples.

From Browser (JavaScript)

const response = await fetch('https://entropydice.onrender.com/roll?q=4D6+D12');
const data = await response.json();
console.log(`Total: ${data.total}`);   // → Total: 22
console.log(`Detail: ${data.detail}`); // → Detail: [4+2+6+1]+[9]

From curl (terminal)

# JSON response
curl "https://entropydice.onrender.com/roll?q=4D6%2BD12"

# Text response (human readable)
curl "https://entropydice.onrender.com/roll?q=4D6%2BD12&format=text"
# → [4+2+6+1]+[9] = 22

# Raw response (just the number)
curl "https://entropydice.onrender.com/roll?q=4D6&format=raw"
# → 13

# Use in a shell script:
RESULT=$(curl -s "https://entropydice.onrender.com/roll?q=D20&format=raw")
echo "You rolled: $RESULT"

From Python

import requests

# Roll 4d6 + d12
r = requests.get("https://entropydice.onrender.com/roll", params={
    "q": "4D6+D12"
})
data = r.json()
print(f"Detail: {data['detail']}")
print(f"Total:  {data['total']}")

# Roll with modifier and custom source
r = requests.get("https://entropydice.onrender.com/roll", params={
    "q": "2D8+1D20-4",
    "source": "crypto-xoshiro-ng",
    "format": "raw"
})
print(f"Result: {r.text}")  # → 32

From Android (Kotlin)

// Using OkHttp
import okhttp3.OkHttpClient
import okhttp3.Request
import org.json.JSONObject

val client = OkHttpClient()

val request = Request.Builder()
    .url("https://entropydice.onrender.com/roll?q=4D6")
    .build()

client.newCall(request).execute().use { response ->
    val json = JSONObject(response.body!!.string())
    val total = json.getInt("total")
    val detail = json.getString("detail")
    textView.text = "🎲 $detail = $total"
}

// Using Retrofit
interface DiceApi {
    @GET("roll")
    suspend fun rollDice(
        @Query("q") expression: String,
        @Query("format") format: String = "json"
    ): ResponseBody
}

From Telegram Bot (Python)

import requests
from telegram import Update
from telegram.ext import Application, CommandHandler

API_URL = "https://entropydice.onrender.com/roll"

async def roll_command(update: Update, context):
    expression = context.args[0] if context.args else "D20"

    r = requests.get(API_URL, params={
        "q": expression,
        "format": "text"
    })

    await update.message.reply_text(
        f"🎲 *{expression}*\n`{r.text}`",
        parse_mode="Markdown"
    )

app = Application.builder().token("YOUR_TOKEN").build()
app.add_handler(CommandHandler("roll", roll_command))
app.run_polling()

Errors return a JSON response with an error field and the appropriate HTTP status code.

StatusSituationExample
400 Missing or invalid q parameter {"ok":false,"error":"Falta el parámetro \"q\"..."}
400 Invalid dice sides {"ok":false,"error":"Caras no válidas: D7..."}
400 Invalid expression syntax {"ok":false,"error":"Carácter inesperado: 'X'"}
400 Division by zero {"ok":false,"error":"División por cero"}
400 Invalid source name {"ok":false,"error":"Fuente no válida: 'foo'..."}
429 Rate limit exceeded (burst or daily) {"ok":false,"error":"Demasiadas peticiones..."}
403 IP permanently banned {"ok":false,"error":"IP bloqueada permanentemente..."}
500 Internal server error {"ok":false,"error":"..."}

Rate Limits

The /roll endpoint is protected by a two-layer rate limiting system to ensure fair usage and prevent abuse.

Burst Limit

No more than 120 requests per minute per IP address. Exceeding this returns a 429 Too Many Requests response. Standard X-RateLimit-* headers are included in every response.

Daily Limit

No more than 7200 requests per day per IP address. Each response includes X-RateLimit-Daily-Limit and X-RateLimit-Daily-Remaining headers.

Ban System

Each time an IP exceeds the daily limit, it accumulates a strike. After 3 consecutive strikes, the IP is permanently banned and receives 403 Forbidden on all future requests.

Strikes expire after 24 hours of good behaviour (no daily-limit violations). The data is persisted to a JSON file and survives server restarts.

Planned Features

Features under consideration for future versions:

  • max(a, b) and min(a, b) — highest/lowest of two expressions
  • d (drop) operator — e.g. 4D6d1 to drop the lowest die
  • k (keep) operator — e.g. 4D6k3 to keep the 3 highest dice
  • Advantage/disadvantage notation: ADV(D20), DIS(D20)

name parameter

When managing a game session with multiple players or NPCs, a name (or user) parameter would let you tag each roll with a player or character identifier — e.g., Player-1, Esqueleto-3, murciélago. The API would echo this field back in the response, making it trivial for clients to assign each result to the right actor in the scene.

Colored dice / parallel groups

Some games roll dice of different colours that form separate operation groups rather than a single combined expression. For example, rolling 2 green dice and 3 white dice at the same time: each colour pool is evaluated independently. This feature would need careful design to express colour groups in the query string while keeping the syntax intuitive.

Raw-dice mode (no calculation)

A response mode that returns only the individual die results without performing any arithmetic. For instance, 3D6 would yield [6][6][6] and 2D8+4 would yield [8][8][4] (operators and modifiers are ignored). This is useful for debugging, manual verification, or when the client wants to apply its own math. If the expression contains no dice at all — e.g. 2+4+6 — the values would be returned as literal results [2][4][6].
